# Intent: ให้คนในพื้นที่รายงานจุดน้ำท่วม

> ตัวอย่างเพื่อการเรียนเท่านั้น ไม่ใช่ประกาศเตือนภัยทางการ

## Problem

คนในพื้นที่และคนที่กำลังจะเดินทางในกรุงเทพฯ ต้องตัดสินใจทันทีว่าถนนหรือซอยที่จะไป "ตอนนี้ผ่านได้ไหม" หรือควรเลี่ยง
แต่ตอนนี้แอปมีแค่ระดับน้ำจากสถานีวัดในคลอง (`GET /districts/:id`) ซึ่งไม่ได้บอกว่าน้ำบนถนนลึกแค่ไหน และสถานีก็มีไม่ครบทุกจุด
คนที่อยู่หน้างานเห็นน้ำท่วมกับตาแต่ยังไม่มีช่องทางส่งข้อมูลนั้นให้คนอื่นใช้

ผู้ใช้หลักคือคนในเขตเดียวกันที่ต้องตัดสินใจเรื่องการเดินทาง ส่วนเจ้าหน้าที่และอาสาสมัครยังไม่อยู่ในขอบเขตรอบนี้

## Proposed outcome

ทำเสร็จแล้ว ใครก็ได้ส่งรายงานจุดน้ำท่วมได้โดยไม่ต้องระบุตัวตน และคนอื่นเห็นรายงานที่ยังไม่หมดอายุของแต่ละเขตได้ทันที

**ข้อมูลในรายงาน**

- **เขต:** เลือกจาก 12 เขตใน `src/districts.ts` เท่านั้น
- **จุดสังเกต:** ข้อความสั้นไม่เกิน 100 ตัวอักษร เช่น "ปากซอยลาดพร้าว 71" ไม่มีพิกัด
- **ความลึก:** จำนวนเต็มหน่วยเซนติเมตร รับค่า 1–200
- **เวลาที่เห็น:** ต้องไม่อยู่ในอนาคต (เผื่อนาฬิกาคลาดเคลื่อนได้ 5 นาที) และไม่เก่าจนหมดอายุไปแล้ว (3 ชั่วโมง) เก็บเป็น UTC แสดงเป็นเวลากรุงเทพฯ

**พฤติกรรม**

- รายงานขึ้นทันทีโดยไม่มีคนตรวจ และติดป้าย "รายงานจากประชาชน ยังไม่ได้ตรวจสอบ"
- แสดงแยกจากค่าของสถานีวัด ไม่นำมาปนหรือคำนวณรวมกัน
- รายงานหมดอายุเมื่อผ่านไป 3 ชั่วโมงนับจาก**เวลาที่เห็น** หมดอายุแล้วไม่แสดงในหน้าสาธารณะ
- ระบบคำนวณระดับความรุนแรงจากความลึก (ค่าตั้งต้น ยังต้องให้คนที่รู้เรื่องยืนยัน)
  - `< 10 cm` เปียก ผ่านได้
  - `10–29 cm` รถเล็กควรระวัง
  - `30–49 cm` รถเก๋งไม่ควรผ่าน
  - `≥ 50 cm` อันตราย ไม่ควรผ่าน
- รวมรายงานซ้ำที่อยู่เขตเดียวกันและจุดสังเกตใกล้เคียงกัน (รายละเอียดไปตัดสินในขั้น spec)
- ลดรายงานปลอมด้วยการจำกัดจำนวนครั้งที่ส่งได้ (rate limit) การรวมรายงานซ้ำ และการหมดอายุ แทนการยืนยันตัวตน

**วัดผลอย่างไร**

1. เกณฑ์ว่างานเสร็จ ตรวจด้วย test ใน repo ทั้งหมด
   - ส่งรายงานที่ถูกต้องแล้วเห็นในเขตนั้นในคำขอถัดไป
   - ข้อมูลผิดทุกกรณีได้ 400 พร้อมเหตุผล ได้แก่ เขตที่ไม่มีในรายการ, ความลึกนอกช่วง, เวลาในอนาคต, เวลาเก่ากว่า 3 ชม., จุดสังเกตยาวเกิน
   - รายงานที่เกิน 3 ชม. ไม่แสดง
   - ระดับความรุนแรงตรงตามเกณฑ์ข้างบน
   - ทุก response มี `NOTICE`
   - ไม่มีข้อมูลส่วนบุคคลใน log
   - ไม่มีโค้ดส่วนไหนเขียนข้อมูลไปที่ `flood-api.rooptanjai.com`
2. ตัวชี้วัดการใช้งานจริง (ถ้านำไปใช้) นับแบบรวมเท่านั้น ไม่ผูกกับตัวบุคคล
   - จำนวนรายงานที่ยังไม่หมดอายุต่อเขตในช่วงฝนตก
   - สัดส่วนรายงานที่ถูกปฏิเสธ
   - ระยะห่างจากเวลาที่เห็นถึงเวลาที่ส่ง

## Constraints

**ความปลอดภัยและความเป็นส่วนตัว**

- ไม่เก็บข้อมูลที่ชี้ตัวคนได้ ไม่มีชื่อ เบอร์โทร หรือบัญชีผู้ใช้
- จุดสังเกตเป็นข้อมูลที่ผู้ใช้พิมพ์เข้ามาเองและเชื่อไม่ได้ ต้องตรวจความยาว และ escape ก่อนแสดงผล
- คนอาจพิมพ์เบอร์โทรหรือชื่อลงในช่องจุดสังเกต ห้ามให้ข้อมูลนั้นหลุดลง log
- ต้องมี rate limit กันสแปม
- ทุก response ต้องแนบ `NOTICE` ว่าเป็นตัวอย่างเพื่อการเรียน ไม่ใช่ประกาศเตือนภัยทางการ

**งบและโครงสร้างพื้นฐาน**

- งบเป็น 0 ไม่ใช้บริการ cloud หรือฐานข้อมูลภายนอก
- เก็บรายงานในหน่วยความจำ (in-memory) ผ่าน interface ที่แยกออกมา (เช่น `ReportStore`) เพื่อเปลี่ยนที่เก็บภายหลังได้ ยอมรับว่าข้อมูลหายตอน restart
- ไม่เพิ่ม runtime dependency ถ้าไม่จำเป็น

**กติกาของ repo**

- ความลึกเป็นจำนวนเต็มหน่วยเซนติเมตร
- เวลาเก็บเป็น UTC แสดงเป็นเวลากรุงเทพฯ (UTC+7)
- ส่ง `now` ผ่าน `Context` เพื่อให้ test ควบคุมเวลาได้
- routing อยู่ใน `handle()` ที่ไม่ผูกกับ `node:http`

**สิ่งที่ห้ามแตะ**

- **ห้ามส่งหรือลบรายงานที่ ROOP TAN JAI Flood Watch (`flood-api.rooptanjai.com`)** ซึ่งเป็นระบบจริงที่คนใช้ตัดสินใจในช่วงน้ำท่วม อ่าน (GET) ได้อย่างเดียว
- ห้ามแก้ค่าระดับน้ำของสถานีวัดใน `data/stations.json` และห้ามให้รายงานจากประชาชนไปปนกับข้อมูลสถานี
- ไม่เปลี่ยน response ของ endpoint เดิมในแบบที่ทำให้ผู้ใช้เดิมพัง ถ้าจะเพิ่มก็เพิ่มได้
